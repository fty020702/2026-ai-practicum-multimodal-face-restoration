# 反向方案调研：冻结文生图模型，新增「参考图分支」，文本通路保持原生且冻结

> 用户提问（2026-11-13）：「能否冻结一个文生图模型，文本输入这块改为我们的方案，这样文本输入也可以冻结，只训参考图输入。这样原生模型的文本理解能力不会变化，且额外增加参考图片输入。有没有先例？可以直接拿来用的？或者这条路走不通的结论？」

---

## 0. 结论先行

**这条路走得通，而且是过去三年最成熟的 adapter 范式之一；但它不是「新发现」，而且在我们选定的基座上已经由官方做完了。**

1. **有先例，且是标准答案**：IP-Adapter（Ye et al., arXiv 2308.06721, 2023, Tencent AI Lab）做的就是「冻结整个文生图模型（含文本编码器与文本 cross-attention），只训练新增的图像条件通路」——约 22M 参数、解耦交叉注意力、文本与图像各走一条 K/V。ControlNet（2023）是同一思路的**空间对齐**版本。二者都是「冻结 T2I + 训参考/条件分支」。
2. **有可直接拿来用的权重与 API**：SD1.5/SDXL 的 `h94/IP-Adapter`、FLUX.1-dev 的 `XLabs-AI/flux-ip-adapter` 与 `InstantX/FLUX.1-dev-IP-Adapter`；本地 `diffusers 0.37.1` 已实测 `FluxPipeline` / `StableDiffusionXLPipeline` 自带 `load_ip_adapter()` + `set_ip_adapter_scale()`。
3. **但在 `FLUX.2 [klein] 4B Base` 上不需要自己训**：官方原生支持多参考图输入（最多 4 张），参考图走 VAE latent → 拼进**图像流**，文本走 Qwen3 → `encoder_hidden_states`，两条流互不占用。本地实测 `Flux2KleinPipeline` 反而**没有** `load_ip_adapter`（因为不需要）。本项目已下载的 15.98 GB BF16 权重直接可用。
4. **「原生文本理解能力不会变化」只在权重层面成立，行为层面不成立**：冻结只保证参数不变；新增图像条件会与文本在注意力 / CFG 中竞争，社区模型卡与后续论文都明确记录了「图像权重调高 → 文本遵循下降」。这不是猜测，有量化证据（见 §5）。
5. **恢复任务要特别小心**：CLIP/SigLIP 语义级参考（IP-Adapter / Redux）**不保像素与结构**，不适合老照片修复这种需要空间对齐的任务；应选 ControlNet / VAE-latent 序列拼接 / Fill-Kontext 式条件。恢复领域已有的「冻结主干 + 训练条件分支」工作（InstructRestore、SPIRE ECCV 2024）用的都是 ControlNet 式空间分支，不是 IP-Adapter 式语义分支。
6. **没有「这条路走不通」的结论**；真正走不通的是它在本项目里的**前提**：DeepSeek 原方案假设「参考图占据了文本输入分支」——本项目已从 diffusers 源码核实这在 FLUX.2 上不成立（参考图在图像流）。因此无论正反两个方向，FLUX.2 都**不需要新增分支**；项目真正该解决的仍是「让文本被训练目标需要」（一图多目标）。

## 1. 形式化：这正是当前项目的镜像

记冻结主干参数 `θ`，预训练文本条件 `c_txt`，参考图条件 `c_img`，目标任务 `y`。

| | 冻结 | 可训练 | 原生文本 |
|---|---|---|---|
| **当前项目（原方案）** | `θ` + 参考图通路 `c_img` | 新增文本旁路 `f_txt` | 被我们冻结成常量 `NEUTRAL_PROMPT`，用户文本走旁路 |
| **用户新方案（反向）** | `θ` + 文本通路 `c_txt` | 新增参考图旁路 `f_img` | 完全保留，不改动 |
| **IP-Adapter** | `θ` + CLIP text + 原 cross-attn | `image_proj` + 每层新增 K/V | 完全保留 |
| **ControlNet** | `θ` + 文本通路 | UNet encoder 副本 + zero-conv | 完全保留 |

数学上二者同构：都是 `out = frozen_backbone(x_t, c_fixed) + λ · g_new(c_new)`，其中 `g_new` 零初始化保证 identity-at-init。**本项目的 `src/condition/bypass.py::DecoupledTextCrossAttention` 只需把 Q 的来源与 K/V 的来源对调，就能直接变成参考图旁路**；`src/condition/freeze.py` 与 hook 注入机制完全复用。所以「能不能实现」不是问题，问题是「有没有必要」。

| **FLUX.1 Redux**（BFL 官方 Tools） | 2024 | FLUX.1 dev 主干 | Redux image encoder（SigLIP 风格） | **把图像 token 拼到 T5 文本序列**：`txt = torch.cat((txt, img_cond), dim=-2)` | ⚠ 这是真正「参考图挤进文本流」的案例 |

| **SPIRE** ECCV 2024 | 2024 | UNet（frozen） | ControlNet 恢复分支 + 调制融合层 | 低质图下采样后拼进 ControlNet 编码器 | ✓ 文本走冻结 CLIP + causal Transformer |

## 5. 「原生文本理解能力不会变化」—— 必须拆成两层

| 层面 | 是否成立 | 证据 |
|---|---|---|
| **权重 / 参数** | ✓ 成立 | `requires_grad_(False)` 后文本编码器与主干权重逐位不变；本项目 `check_gradient_isolation()` 已验证零梯度泄漏 |
| **行为 / 输出分布** | ✗ **不保证** | 新增条件改变注意力归一化、CFG 平衡和去噪轨迹 |

具体证据：

- InstantX 官方模型卡原话：`"image work just like text, so it may not be responsive or interfere with other text"` —— 明确承认图像条件会**干扰文本响应**；同一张卡还列出 content leakage ↔ style transfer 的权衡与多样性受限。
- **Conceptrol**（arXiv 2503.06568）：量化了 IP-Adapter 里图像条件注意力图的定位精度，最高 AUC 仅 **0.38**，而文本注意力 AUC 可达 **0.99**；`IP Scale` 调低 → 概念保不住，调高 → 偏离文本 prompt 并出现 copy-paste。
- **DynaIP**（ECCV 2026）：把这个问题命名为 **Concept Preservation vs Prompt Following 的不可调和权衡**，并专门提出 MM-DiT 双流解耦 + 推理时剪掉文本分支注入来缓解。
- **SPIRE**（ECCV 2024）在恢复任务上的负面结论更直接：**把语义提示零样本注入基线会降低性能**，有效的提示条件化必须联合训练。

所以正确说法是：**「原生文本权重不变」✓；「原生文本能力不变」需要实测，不能假设。** 本项目已有的 `scripts/diagnose_text_usage.py`（换错文本是否涨 loss）与 `scripts/diagnose_ambiguity.py`（一图多目标下的 wrong penalty）正好就是量这件事的工具，可以直接迁移到反向方案上做 A/B。

## 6. 「走不通」的部分到底是什么

**不是架构走不通，而是下面四条具体限制**，任何一条踩中都会让方案失效：

1. **在 FLUX.2 上是重复造轮子**。官方 `image=` 已实现多参考图 + 原生文本，且走的是 VAE latent 序列拼接（保空间结构），比自己训一个 CLIP 语义旁路更适合恢复。再训一条旁路只会增加显存与干扰。
2. **训练成本与 4070Ti 12 GB 不匹配**。IP-Adapter 原论文用约 10M 图文对、8×V100、1M steps；InstantX FLUX 版 10M 数据 / batch 128 / 80k steps。`[REPORTED]` 从零训一个参考图分支在本机不现实；**复用现成权重**才是可行路径。
3. **语义级参考 ≠ 像素级恢复**。IP-Adapter / Redux 用 CLIP/SigLIP 全局特征，没有 mask、没有空间定位，输出是「风格与内容相似的新图」，不是「同一张老照片的修复结果」。老照片修复要求划痕位置、人脸结构一一对应，必须走 ControlNet / VAE-latent / Fill 式空间条件。
4. **冻结不等于解耦**。图像与文本条件在注意力里仍会争抢；`λ`（IP scale / CFG）成了新的必须调的超参，而且没有理论最优值。这也是 Conceptrol / DynaIP 后续整篇论文要解决的问题。

**额外一条方法论结论**：DeepSeek 原方案与用户新方案都预设「参考图占据了文本分支」。这个前提**只在 FLUX.1 Redux 这类把图像 token 拼进 T5 序列的模型上成立**，在 FLUX.2 / Kontext / ControlNet 上都不成立。所以「把文本从被占据的分支里救出来」这个动机，对我们选定的基座而言并不存在。

## 7. 对本项目的建议

| 路线 | 做法 | 价值 | 建议 |
|---|---|---|---|
| **A（推荐）** | 直接用 `Flux2KleinPipeline(image=[...])`，冻结 transformer + Qwen3，把工程精力放回「一图多目标文本消歧」 | 零训练成本，保留原生文本理解，立刻能跑 | ✅ 主线 |
| **B（对照实验）** | SDXL + diffusers IP-Adapter，复刻「冻结文本 + 训参考图旁路」，用 `diagnose_text_usage.py` 量文本遵循是否下降 | 能给「权重不变 ≠ 行为不变」补一个本地 `[RESULT]` | ⭕ 有价值但非必要 |
| **C（恢复专用）** | ControlNet 式空间条件分支（InstructRestore / SPIRE 范式） | 像素对齐，适合老照片 | ⭕ 若后续要真做恢复质量再上 |
| **D（不建议）** | 在 FLUX.2 上再训一条 IP-Adapter 式参考图旁路 | 与官方 `image=` 功能重叠 | ❌ |

> **与最新实验的呼应**：2026-11-13 自建「老照片 + 文本 → 4 个不同高清目标」数据集的严格 A/B 只得到 `penalty/gap = 7.28%`（32 组探针）/ `9.30%`（8 组），对照 `0.03%` / `0.80%`，**方向对但未过 10% 阈值**，verdict `NOT-YET-SUPPORTED`。这说明数据构造本身仍是最难的一环，而不是分支架构；换架构（反向方案）不会自动解决「文本是否被训练目标需要」的问题。详见 `outputs/logs/old_photo_multitarget_summary.json`。

`guidance_scale=4.0` / `seed=20261113`，**零训练**（transformer 与 Qwen3 原生冻结），

**组 A — 修复风格（99 s / 4 张，`--prompt-set restore --tag old_photo`）**
