## 0. 先回答一个问题：为什么"真实数据集"不等于"真实配对老照片"

用户要求「我要真实数据集」。但在这个任务里必须先说清一个硬约束：

**真实历史老照片几乎不存在像素级对齐的干净 GT。** 你不可能拿到 1920 年那张照片
"没有划痕、没有褪色、没有折痕"的原始版本。因此所有主流论文都不用
「真实老照片 → 干净老照片」配对做监督训练，而是采用同一套三段式配方：

```
① 真实现代高清照片 (DIV2K / VOC / FFHQ / ADE20K)  ← 这是"真实图像"，不是程序化合成
        │  物理退化模型（模拟老化）
        ▼
② 合成配对 (degraded, clean)  → 有 GT，可做 PSNR/SSIM/LPIPS 监督训练
        │
        ▼
③ 真实老照片（无 GT）  → 域适配 / 无参考 IQA / 用户研究
```

`[PAPER]` Wan et al. CVPR 2020 明确把退化拆成两类，并分别设计网络分支：

| 类别 | 缺陷 | 论文里的处理 |
|---|---|---|
| **structured（结构化）** | scratches、dust spots、holes/tears、paper texture | 收集真实划痕 / 纸张纹理，弹性形变，layer addition / lighten-only / screen 混合，羽化孔洞露出 paper texture；local non-local block |
| **unstructured（非结构化）** | noise、blur、film grain、fading | global 分支统一处理 |

**结论**：本项目原先的 64×64 程序化渐变+色块图（synthetic）确实不能用于恢复质量训练；
但正确的替代不是"去找配对的真实老照片"，而是**用真实高清照片 + 论文式物理退化管线
构造配对，并把真实老照片单独留作无 GT 评测**。这正是本次落地的内容。

## 1. 论文对标：它们到底怎么做的

### 1.1 Bringing Old Photos Back to Life（Wan et al., CVPR 2020 Oral；TPAMI 2022）

`[PAPER]` 老照片修复的奠基工作，也是本项目退化管线的主要对标对象。

| 维度 | 做法 |
|---|---|
| 核心思路 | **triplet domain translation**：两个 VAE 分别把 old / clean 映射到 latent，用合成配对学 latent 之间的变换，缩小合成域与真实域的 domain gap |
| 训练数据 | 用 **Pascal VOC** 图像合成旧照片；收集 scratch / paper textures；弹性形变；layer addition / lighten-only / screen 混合；生成 feathered holes 露出 paper texture；叠加 film grain noise、blur |
| 真实老照片 | 收集 **5,718** 张；其中 **783** 张标注 scratches，**400** 张用于 finetune scratch detection U-Net（论文报告 AUC **0.91**） |
| crop | 训练随机裁剪 **256×256** |
| 测试 | DIV2K 上合成退化图 + 真实老照片测试集 |
| 指标 | PSNR / SSIM / LPIPS / FID |
| 网络 | global 分支（非结构化）+ local non-local 分支（结构化，latent 空间融合）+ 人脸细化网络 |
| 数据开放 | 官方仓库 `microsoft/Bringing-Old-Photos-Back-to-Life` 提供 `test_images/old` 与 `test_images/old_w_scratch`；README 明确说明**带标注的划痕数据集暂不公开** |

> 复现资料（Paddle 版本 Old2Life）报告指标：target 23.33/0.69/134.35/0.25
> (PSNR/SSIM/FID/LPIPS)。该数字来自第三方复现，仅作量级参考。

**对齐到本项目**：`src/data/old_photo.py` 的 `STRUCTURED` / `UNSTRUCTURED`
两套缺陷、screen/lighten-only 式划痕、羽化孔洞、film grain、fading、256×256 crop
全部对标这一篇。clean GT 换成同样被该论文用于测试的 **DIV2K**。

### 1.2 InstructIR: High-Quality Image Restoration Following Human Instructions（ECCV 2024）

`[PAPER]` 这是"文本指令"最直接的对标 —— 我们的新增文本分支就是这类设定。

| 维度 | 做法 |
|---|---|
| 任务 | all-in-one restoration，用**自然语言指令**告诉模型修什么 |
| Prompt 构造 | 用 **GPT-4 生成 >10,000 条** prompts，覆盖 **7 个**任务；训练时**按退化类型随机采样** prompt，而不是一条退化绑死一句话 |
| 文本编码器 | **BGE-micro-v2** sentence encoder（不是 CLIP） |
| 数据混合 | BSD400 + WED（去噪，约 5,000 张，Gaussian σ=15/25/50）；Rain100L（200 train / 100 test）；RESIDE SOTS（过滤后 2,000 train / 500 test）；GoPro（2,103 / 1,111）；LOL v1（485 / 15，真实低光配对）；MIT5K（1,000 / 500） |
| 指令示例 | `Can you clean the dots from my image?` / `Remove the noise from my picture` / `My picture's not sharp, fix it` / `Remove the fog from my photo` / `Increase the illumination in this shot` / `Make it pop!` |

**对齐到本项目**：这是最关键的一点 —— 原 toy 数据把 `task` 和 `prompt` 用
`i % 6` 严格绑定，导致"文本是否有用"的消融**不可证伪**（模型可以从图像直接推断任务，
完全忽略文本）。`OldPhotoDataset` 按 InstructIR 的思路改为：
随机缺陷组合 + instruction 是噪声子集（随机丢弃一条 + 随机注入一条未施加的干扰指令）
+ 每张图 `prompts_per_image=3` 条不同文本 + 真实 caption 池解耦。

### 1.3 Time-Travel Rephotography（ACM TOG 2020）

`[PAPER]` 真实历史照片评测范式的代表。

| 维度 | 做法 |
|---|---|
| 数据 | **Historical Wiki Face Dataset**：224 张历史人物人脸 crop；与专业摄影师用现代 DSLR + 19 世纪 gelatin dry plate 工艺采集**少量真实配对** |
| 先验 | FFHQ 现代人脸 + StyleGAN2 latent optimization |
| 退化 | physically-based degradation model（spectral sensitivity、camera response、lens blur） |
| 评测 | **NIQE 无参考指标** + 用户研究（39 人 × 224 图 × 3 baseline） |
| 结果 | NIQE：input 7.08 → best baseline 5.47 → 本方法 4.55；用户偏好 58.9% vs 29.4%，11.7% 无强偏好 |

**对齐到本项目**：真实老照片**不做训练配对**，只进 `eval_real.jsonl`，
评测走无参考 IQA / 用户研究，不用 PSNR。

### 1.4 Modernizing Old Photos Using Multiple References（CVPR 2023）

`[PAPER]` 明确区分两套评测：

- 合成评估：从 **ADE20K val** 生成 **1,000** 个 synthetic degraded + reference 对，
  用 PSNR / SSIM / LPIPS；
- 真实老照片 **CHD testing set**：无 GT，用 **NIQE / BRISQUE** 等 no-reference IQA。

### 1.5 LL-Bench / 老照片修复质量评价

`[PAPER]`  newer benchmark 强调：真实老照片没有 clean GT，因此不能只用 PSNR/SSIM，
要用 no-reference IQA 并以 SRCC / accuracy 对齐人类偏好。涉及的指标 / 模型：
FGResQ、Q-Align、DeQA-Score、CLIPIQA、NIQE、BRISQUE、MusIQ、MANIQA、
HPSv3、ImageReward 等。

### 1.6 对标总表

| | GT 来源 | 退化 | 文本 | 真实老照片用途 | 指标 |
|---|---|---|---|---|---|
| Wan 2020 | Pascal VOC | 结构化+非结构化物理退化 | 无 | 域适配 / 测试 | PSNR/SSIM/LPIPS/FID |
| InstructIR 2024 | 多数据集混合 | 7 类任务退化 | GPT-4 指令（随机采样） | 无 | PSNR/SSIM + 指令跟随 |
| TOG 2020 | FFHQ + 少量真实配对 | 物理成像模型 | 无 | 主评测对象 | NIQE + user study |
| CVPR 2023 多参考 | ADE20K val | 合成退化 + reference | 无 | CHD test set | PSNR/SSIM/LPIPS + NIQE/BRISQUE |
| **本项目** | **DIV2K HR 真实照片** | **对标 Wan 的 11 种缺陷** | **真实 caption + 用户约束，去 confound** | **`eval_real.jsonl`（无 GT）** | **合成：PSNR/SSIM/LPIPS；真实：NIQE/BRISQUE/CLIP-IQA** |

## 2. 本项目落地的真实数据集

### 2.1 数据源（全部在 2026-11-07 验证可直连下载）

| 用途 | 数据源 | 说明 |
|---|---|---|
| clean GT | `mAiello00/DIV2K` → `DIV2K_train_HR/NNNN.png` | 1,200 张真实 2K 照片；DIV2K 正是 Wan et al. 合成测试所用的基准 |

| 真实老照片（无 GT） | `microsoft/Bringing-Old-Photos-Back-to-Life/test_images/{old,old_w_scratch}` | 论文官方测试图；`old_w_scratch` 为带划痕老照片 |
| 真实老照片（无 GT） | `froilo/old_family_photo_dataset` | 真实老家庭照片 |

> 许可：仅用于课程实训 / 研究。请遵守各数据源自身许可（DIV2K、Microsoft、
> HuggingFace 数据集）。

### 2.2 目录与产物

```
data/old_photo/
  hr_raw/         原始下载的 DIV2K 真实高清图（保留，便于换 crop）
  hr/             256×256 随机裁剪后的 clean GT
  degraded/       论文式老化后的配对低质图
  real_old/       真实老照片（无 GT，评测专用）
  captions_raw/   下载的真实 caption 文本
  train.jsonl     配对 manifest：clean / degraded / defects / caption / gt_source
  eval_real.jsonl 真实老照片 manifest：image / prompt / has_gt=false
  captions.json   真实 caption 池
  dataset_info.json  数据来源、规模、缺陷体系、许可说明
```

### 2.3 缺陷体系（`src/data/old_photo.py`）

- **结构化**：`scratches`（细长亮/暗划痕，screen/lighten-only 混合）、
  `dust_spots`、`holes`（不规则羽化孔洞露出纸张底色）、`paper_texture`
- **非结构化**：`film_grain`（信号相关颗粒）、`blur`、`fading`（对比度损失+抬黑场）、
  `sepia`（泛黄色偏）、`jpeg`、`vignette`（暗角）、`resolution_loss`
- 每张图随机采样 **2–5 种组合**（`sample_defect_plan`），至少 1 种非结构化缺陷；
  强度随机。这是反 confound 的第一层。

### 2.4 反 confound：让 `d_text` 消融真正可证伪 `[FACT]`

原 `RestorationDataset` 的问题（`docs/方案设计.md` 早已记录）：
`task = tasks[i % 6]`、`content = CONTENT_HINTS[i % 6]`，退化类型与 prompt 严格一一对应。
这样"模型响应文本"完全可能被"模型从参考图看出这是噪声图"解释掉。

`OldPhotoDataset` 的四层修复：

1. 每张图是**随机缺陷组合**，不是单一 task label；
2. task prompt 是缺陷集合的**噪声子集**：60% 概率随机丢一条真实指令，
   45% 概率注入一条**未施加**的干扰指令；
3. 内容级文本来自**真实 caption 池**并与退化类型解耦；`variant>0` 时换成同池另一条
   caption，实现「**同一张图，只改文本**」；
4. 叠加 `USER_CONSTRAINTS`（`preserve facial identity`、`keep the original sepia tone`、
   `do not over-smooth fabric` …）—— 这才是本项目真正要研究的「用户新增文本」，
   它无法从图像退化中推断出来。

每张图重复 `prompts_per_image=3` 次，用 `(seed + i*7919 + v*104729)` 派生局部 RNG，
**与 DataLoader shuffle / worker 数无关，可复现**。

### 2.5 评测方案（对标论文，分两套，不能混）

| 集合 | 有无 GT | 指标 |
|---|---|---|
| `train.jsonl` 的 held-out 合成配对 | 有 | **PSNR / SSIM / LPIPS / FID**（现有 `src/evaluate.py` 已实现 PSNR/SSIM/LPIPS） |
| `eval_real.jsonl` 真实老照片 | **无** | **NIQE / BRISQUE / CLIP-IQA / MUSIQ** + 用户偏好研究；**禁止**报 PSNR |

`[UNVERIFIED]` 无参考指标依赖 `pyiqa` / `piq` 等包，当前 ChatAI 环境未安装，
因此工程里先保留接口与 manifest，不在本轮强行安装。

## 3. 怎么跑

```bat
set P=D:/Anaconda/envs/ChatAI/python.exe
set R=G:/研究生生涯相关/课程/人工智能系统实训

REM 1) 构建真实数据集（可重复运行，已下载文件自动跳过）
%P% %R%/scripts/build_old_photo_data.py --gt 24 --captions 48 --real-old 14 --size 256

REM 2) 可视化：真实 clean / degraded / prompt + 真实老照片评测集
%P% %R%/scripts/show_old_photo_example.py

REM 3) 训练（toy 主干做架构验证；真实基座需切 backend.name=flux2_klein）
%P% %R%/src/train.py --override %R%/configs/old_photo.yaml --steps 300

REM 4) 文本响应消融（验证用户文本真的生效）
%P% %R%/scripts/run_ablation.py --override %R%/configs/old_photo.yaml
```

**换成你自己的真实老照片**：把图片放进 `data/raw/`，然后

```bat
%P% %R%/scripts/build_old_photo_data.py --offline --size 256
```

`--offline` 完全不联网，用你自己的真实照片作为 GT；**不会**静默回退到 synthetic toy 图。

## 4. 与原有工程的关系 / 事实分级

- `[FACT]` `make_dataset()` 按 `data.source` 分发；`configs/default.yaml` **没有**
  `data.source` 字段，因此所有原有 toy 实验（smoke test T1–T6、A/B/C/D 消融）
  走的是**完全相同的 `RestorationDataset`**，数值逐位不变。
- `[FACT]` 新数据集的 batch 契约与旧数据集一致（`clean`/`degraded`/`task`/`prompt`），
  额外多一个 `defects` 字符串字段，`train.py` / `evaluate.py` 无需改计算逻辑。
- `[FACT]` 真实老照片只有 `eval_real.jsonl`，**不进入任何 (clean, degraded) 训练对**。
- `[INFERENCE]` 用 DIV2K 现代照片模拟老化仍有 domain gap；这正是 Wan et al. 用
  triplet domain translation 要解决的问题。当前工程只做「有配对监督」这一半，
  未实现真实域适配分支。
- `[UNVERIFIED]` FLUX.2 [klein] 4B Base 上的真实端到端训练：BF16 权重已下载并
  完成 CPU 结构探测；离线 Qwen3 prompt 预编码受限于本机可用物理内存
  （实测 3.6–4.1 GB，而 Qwen3-4B BF16 权重本身 ~8 GB）而阻塞，脚本已加
  内存预检并改为分批单条编码（见 `outputs/logs/precompute_prompts.json`）；
  4070 Ti 空闲显存亦长期低于 9 GB 门槛。最新 `verify_real_backend.json`
  的 `verdict=BLOCKED` **仅因这一项**，权重与结构契约均已 OK。
- `[PAPER]` 本文所有论文数字为公开资料整理，正式写入报告前请核对原文 PDF。
