# 一图多目标 / 文本消歧：数据集与论文对标

> 触发问题（用户，2026-11-12）：
> 1. 文本要提供**图像里没有的信息**；
> 2. **同一个低清图配多个高清目标**，不同高清图对应不同文本输入；
> 3. 找下数据集看看。
>
> 本文回答第 3 点，并说明前两点为什么是同一个数学条件的两面。
> 事实分级：`[FACT]` 论文 / 官方仓库可查；`[RESULT]` 本项目本地实测；`[INFERENCE]` 推断。

---

## 0. 结论先行

**您提的三点是对的，而且正好补上本项目现在最致命的漏洞。**

当前 `OldPhotoDataset` 给同一张退化图配了 `prompts_per_image=3` 条不同文本，
但 **clean GT 只有一个**。在这种数据上，条件分布 `p(y | x, text)` 对 `text` 退化成
`p(y | x)`：换文本不改变目标，MSE 最优解就是忽略文本。这解释了
`scripts/diagnose_text_usage.py` 的实测结果 `[RESULT]`——100 步训练后换错误文本
只让 loss 变 `0.00390625`（1 个 bf16 ULP，相对 1.08%），而「有文本 vs 无文本」
降 loss 5.39%。文本学到的是**通用有益偏置**，不是指令控制。

要逼模型用文本，唯一严格的做法是让 **同一个 x 对应多个不同的 y**，
且 `y` 由 `text` 唯一决定。此时：

```
无文本模型的最优预测  ȳ = (1/K) Σ_k y_k
无文本 MSE 下界       L_no_text = (1/K) Σ_k || y_k − ȳ ||²   > 0
有文本模型的 MSE 下界  L_with_text = 0
---------------------------------------------------------------
ambiguity_gap = L_no_text − L_with_text = Var_k(y_k)
```

严格说这个下界在 **t → 1** 时成立：此时 `x_t = (1−t)x0 + t·x1 ≈ x1` 是纯噪声，
模型输入里没有 `x0` 的痕迹，必须输出 `v ≈ x1 − E[x0 | ref, text]`。若 `t` 很小，
`x_t ≈ x0` 会把目标身份泄漏给模型，文本就可以被绕过 —— 这正是第一轮实验
（`t~U(0,1)`）只拿到 0.6% of gap、第二轮压到 `t~U(0.9,1)` 才拿到 60.6% 的原因。

`ambiguity_gap > 0` 是**数据层面的硬下界**，不需要训练就能算出来。
它把「文本提供图像没有的信息」变成可测量的量，也把「文本是否被利用」
变成可证伪的判据：`loss(wrong text) − loss(own text)` 应显著大于 0。

**关键副产品**：这个设定下**不需要改 loss**。纯 velocity MSE 就会惩罚忽略文本的
模型，因为「预测所有目标的平均值」必然产生梯度。之前考虑过加文本对比 /
对齐损失，其实那是在补数据设计的洞，现在可以先把洞堵上。

### 1.3 老照片任务为什么「一图多目标」特别自然 `[INFERENCE]`

老照片修复里最经典的**不适定多解**就是色调：

- 同一张褪色 / 带色偏的老照片，可以合理地输出
  **自然彩色** / **黑白原貌** / **保留棕褐 sepia** / **只去划痕、保留年代颗粒**。
- 商业修复工具本来就会同时给出 full color、B&W、sepia 三个版本。
- 学术上 colorization 被明确视为 *plausible reconstruction* 而非恢复原始波长
  （CIN25、Text2Colors 都论证了多解性）。
- 因此「用户想要哪种版本」**在退化图里根本不存在**，只能由文本给出——
  这正好满足您的第 1 点，且不需要生成模型去造伪目标。

## 2. 本项目的选型（务实约束）

**不直接下载上面任何一个大数据集**，理由：

1. `4070 Ti` 12GB + 已下载 15.98GB FLUX.2 权重，磁盘 / 显存都紧；
   InstructPix2Pix 最小版本 436GB，RFIR 全量未正式开放。
2. 本项目要验证的是**文本分支是否被训练目标需要**，需要的是
   「同一 x / 多个可控且像素明显不同的 y / 文本唯一决定 y」的**干净对照**，
   不是大规模语义多样性。大数据集反而引入 confound。
3. 真实老照片没有 pixel-aligned GT（所有论文一致），不可能直接拿来做配对监督。

**采用：自建 A 类数据集，建立在已有的真实 DIV2K GT 上。**

```
data/old_photo/hr/*.png          24 张真实 2K 照片的 256×256 crop（已落盘）
        │
        ├─ 共享退化 x（一张）：sepia + fading + film_grain + scratches + dust + vignette
        │
        └─ K=4 个不同的高清目标 y_k：
             natural_color   原始彩色、完全修复
             monochrome      完全修复但保持黑白
             sepia_tone      完全修复但保留复古棕褐色
             minimal_repair  只去结构性损伤，保留颗粒 / 色偏 / 褪色（保守修复）
```

每个目标绑定一组**以目标风格开头**的 paraphrase（避免 HashTextEncoder 的
8-token 截断把所有 prompt 变成同一个前缀），再加真实 caption 与用户约束，
但 caption / 约束**与目标类型独立采样**，杜绝新的 confound。

对标关系：
- 退化管线沿用 **Wan et al. CVPR 2020** 的 structured / unstructured 分离；
- 「文本指定保留哪些退化」借鉴 **RFIR / PRISM** 的 partial / negative prompt；
- 「多解性」借鉴 **CIN25 / Text2Colors**；
- 「同一个源 + 不同指令 → 不同目标」的生成结构借鉴 **InstructPix2Pix / SEED-Data-Edit**；
- 评测仍按老照片惯例：合成对用 PSNR/SSIM，真实老照片用无参考 IQA + 歧义 gap。

## 3. 新增可证伪指标

`scripts/diagnose_ambiguity.py` 输出（写入 `outputs/logs/ambiguity.json`）：

| 指标 | 含义 | 期望 |
|---|---|---|
| `target_rms_gap` | 同一 x 下 K 个 y 在 token 空间的两两 RMS 差 | > 0，且足够大 |
| `no_text_floor_mse` | `Var_k(y_k)`，无文本模型 MSE 的理论下界 | > 0 |
| `text_feature_gap` | 不同目标文本的 encoder 特征距离 | > 0（确认文本可区分） |
| `loss_own` / `loss_wrong` / `loss_off` | 训练后：正确文本 / 换成同图另一目标的文本 / 关掉文本 | `loss_wrong > loss_own` 且接近 `no_text_floor_mse` 量级 |
| `wrong_text_penalty_relative` | `(loss_wrong − loss_own) / loss_own` | 单目标数据 ≈ 1%；多目标数据应显著更大 |

**对照实验**：用相同步数分别训练 `configs/old_photo.yaml`（单目标）
与 `configs/multi_target.yaml`（多目标），把两者的 `wrong_text_penalty_relative`
放在一张表里。这是把您的方案变成可验证假设的最小闭环。

## 4. 限制与如实声明

- 自建的 4 个目标里，`monochrome` / `sepia_tone` / `minimal_repair` 是**由真实 GT
  做确定性色调变换**得到的合理目标，不是真实拍摄的另一张照片。
  它验证的是「文本能否消歧」，**不是**老照片修复质量或真实用户偏好分布。
- toy 路径的 `HashTextEncoder` 是哈希伪特征，**不证明语言理解**；
  真实语义结论必须走 Qwen3-4B 离线缓存路径。
- 真实 FLUX.2 路径需要为这批新 prompt 重新跑 `precompute_prompts.py`
  （CPU 上约 3 小时 / 10 条，新 prompt 数量更多会更久），且 `train.py` 只接受
  一个 `--override`，所以提供了合并好的 `configs/multi_target_flux2.yaml`。
- 真实历史照片无 GT 的限制没有消失：`data/old_photo/real_old/` 仍只做无参考评测。

## 5. 实验结果 `[RESULT]`（2026-11-12，toy 主干 + 严格 A/B）

### 5.1 实验设计

**唯一的自变量**：GT 是否随文本变化。
`configs/single_target_*` 与 `configs/multi_target_*` 除 `data.collapse_targets`
外**完全相同**：同样的真实照片、同样的退化图、同样的 4 组文本、同样的
prompt paraphrase、同样的 seed / 模型 / 步数 / lr / t 采样。对照组把 K 个目标的
`clean` 路径全部指向第 0 个目标，4 条文本原样保留。

探针（`scripts/diagnose_ambiguity.py`）固定 `x0 / x1 / t / ref`，**只置换文本**，
且 `t=0.999`，避免 `x_t` 泄漏目标身份。

### 5.2 两轮结果

| 轮次 | 配置 | gap `Var_k(y_k)` | wrong penalty / gap | 样式选择性 |
|---|---|---|---|---|
| 1 | 温和色调差、400 步、lr 1e-4、`t~U(0,1)` | 0.00139 | 单 0.15% / **多 0.56%** | 单 1.1% / **多 1.0%** |
| 1 | 同上但 `t~U(0.8,1)` | 0.00139 | 单 0.53% / **多 0.93%** | 单 1.3% / **多 1.2%** |
| 2 | **放大色调差、1200 步、lr 5e-4、`t~U(0.9,1)`** | 0.00547 | 单 **8.95%** / **多 60.61%** | 单 **5.36%** / **多 11.08%** |

第 2 轮关键数字：

- 目标间像素 RMS 均值 **48.61/255**（第 1 轮 24.19），token 空间 gap 提升 **3.9 倍**；
- 多目标 wrong penalty `0.00331368` vs 单目标 `0.00048904` → **6.78 倍**；
- 多目标 penalty 达到理论无文本下界的 **60.61%**，超过预设 10% 支持阈值；
- `d_text_wrong` 0.0698 vs 0.0329，`d_text_onoff` 0.630 vs 0.614 → 样式选择性 **11.08% vs 5.36%**；
- verdict：`TEXT-NECESSITY-SUPPORTED`。

完整数据：`outputs/logs/ambiguity_round1.json`（4 组）、`ambiguity_round2.json`（2 组）、
`ambiguity_summary.json`；图：`outputs/samples/ambiguity_ab.png`。

### 5.3 为什么第 1 轮几乎没效果（三个叠加原因）

1. **目标差异太弱**：`Var_k(y_k)=0.0014`，而 `x1~N(0,1)` 主导的 velocity target
   方差 ≈1.0，样式信号被淹没约 **700 倍**。
2. **`x_t` 泄漏**：`t~U(0,1)` 时小 t 下 `x_t≈x0`，模型不用读文本也能知道目标。
   把 t 压到高噪声端是必要条件（不是可选项）。
3. **文本分支把 4 类 prompt 压成同一个通用偏置**：`d_text_wrong / d_text_onoff`
   只有 1%，而 `loss_off - loss_own ≈ 0.4`（文本 ON 大幅降 loss）。
   即「有文本」有用、「文本对不对」几乎无所谓 —— 与此前 FLUX.2 上的
   `diagnose_text_usage.py` 结论一致。

### 5.4 结论与边界

- **数据设计层面**：用户的三点方案成立，且**不需要改 loss**。
  `Var_k(y_k) > 0` 是硬下界，纯 velocity MSE 在 `t→1` 时必然惩罚忽略文本的模型；
  实测在 toy 上达到下界的 60.6%。
- **`t_min` 是实验性设置**：默认配置仍是 `U(0,1)`，`src/train.py::compute_loss`
  的 `t_range` 在 `(0,1)` 时是严格 no-op，`smoke_test.py` 回归 PASS、
  `T5_d_text_trained=0.000563` 逐位不变。
- **不是真实基座结论**：toy 主干随机初始化且冻结，文本编码器是哈希伪特征。
  这里证明的是「数据构造 + 优化目标」的机制，不是语言理解、恢复质量或
  真实用户偏好。真实 FLUX.2 多目标训练需要先重跑 288 条 prompt 的 Qwen3 离线缓存。
- **4 个目标是确定性色调变换**，不是真实拍摄的另一张照片；老照片无 GT 的
  根本限制没有消失，`data/old_photo/real_old/` 仍只做无参考评测。

```
data/ip2p_500m/raw/train-00000-of-00262-57cebf95b4a9170c.parquet

```

下载耗时 98 秒（首次代理 502，第 2 次成功，Range 断点续传）。
`scripts/fetch_ip2p_shard.py` / `scripts/inspect_ip2p_shard.py` 记录全过程。

### 7.2 格式映射（这是「格式符合要求」的准确含义）

| 官方 triplet | 项目 batch 契约 |
|---|---|
| `original_image` | `degraded` `[3,H,W] float [0,1]` |
| `edited_image` | `clean` `[3,H,W] float [0,1]` |
| `edit_prompt` | `prompt` `str` |
| `original_prompt` | `task` `str`（仅元数据） |

`src/data/ip2p_dataset.py` 直接流式读 parquet，`make_dataset()` 注册
`source: ip2p`。用 `ip2p_max_rows=800` 只用 800/1195 行（748 条不同
`edit_prompt`），对应「不必全部训练」；完整 500MB 分片保留在磁盘。

真实指令样本（不是我编的）：`"Turn it into a photo"`、`"Make it a cartoon."`、
`"make her a scientist"`、`"make the waterfall a rainbow"`。

### 7.3 `[FACT]` 这个分片不是 A 类

`inspect_ip2p_shard.py` 实测：1,195 个 `original_prompt` 全不同、
1,195 个 `original_image` bytes 全不同、`identical_source_image_groups=0`、
`a_class_native=false`。**每个输入只有一个目标**，所以没有 `Var_k(y_k)`
歧义下界。它满足格式，不满足 §0 的数学条件。别把两者混为一谈。

另外 `[FACT]`：官方图像由 Stable Diffusion + Prompt-to-Prompt 生成，
**不是真实拍摄照片**。

### 7.4 训练与证伪检验

`src/train.py --override configs/ip2p_500m.yaml --device cuda --steps 1200`：
28 秒，loss `1.453311 → 1.030900`，4 个 checkpoint。链路完全跑通。

但 `scripts/diagnose_ip2p_text.py`（固定 `x0/x1/t/ref`，只换文本）给出
**负面结果**：

| 量 | 值 |
|---|---|
| `loss_own` | 1.029360 |
| `loss_wrong` | 1.029536 |
| `wrong_penalty` | 0.000176 |
| `wrong_penalty_relative` | **0.017%** |
| `style_selectivity` | 4.57% |
| `loss_off − loss_own` | 0.400355 |
| verdict | `NO TEXT-SPECIFIC RESPONSE` |

和旧 toy 数据一样：文本 ON 大幅降 loss，但「文本对不对」几乎无所谓。
**开放式编辑指令确实携带图像没有的信息，但单目标 + 随机冻结 toy 主干 +
哈希文本编码器下，1200 步不足以把它变成指令特定控制。**

### 7.5 补上 A 类视图后复现 §8.2 结论

用同一分片的真实图像对作 GT 池
（`scripts/build_ip2p_multitarget.py --groups 200`）：

```
x   = 官方 original_image（K 个目标共享）
y0  = 官方 edited_image（原样）
y1..y3 = y0 的确定性风格变换（monochrome / sepia_tone / minimal_repair）
text_k = 风格 paraphrase 放句首 + 真实 edit_prompt 作内容尾
```

200 组 × 4 目标 = 800 样本，目标间像素 RMS **52.67**，
`data/ip2p_500m/` 合计 **574MB**（499.83MB 官方分片 + 74MB 衍生图）。

严格 A/B（唯一变量 `collapse_targets`，同样 1200 步 / CUDA / `t~U(0.9,1)`）：

| | 单目标对照 | A 类 |
|---|---|---|
| `wrong_penalty` | **−0.000054** | **+0.001972** |
| `penalty_to_gap_ratio` | −1.0% | **36.73%** |
| `style_selectivity` | 3.83% | **7.92%** |
| `text_needed_by_loss` | false | **true** |

verdict：`TEXT-NECESSITY-SUPPORTED`。比 §5 的 DIV2K 自建数据（60.61%）
低，合理：这里 `x` 与 `y` 之间本身还隔了一次「编辑」变换，任务更难。

报告：`outputs/logs/ambiguity_ip2p_ab.json`、`ip2p_text_diagnosis.json`、
`ip2p_500m_summary.json`；图：`outputs/samples/ip2p_500m_summary.png`。

### 7.6 边界

- toy 主干随机冻结 + `HashTextEncoder`（非语义）+ 64×64：证明数据设计与
  优化目标机制，**不是**语言理解 / 恢复质量 / 真实 FLUX.2 结论。
- `y1..y3` 是 `y0` 的确定性色调变换，不是独立采集的另一张照片。
- 真实 FLUX.2 需要为 748 条新 `edit_prompt` 重跑 Qwen3 离线缓存
  （CPU 约 3h/10 条）。按「不必全部训练」可取 10–20 条子集试点，
  **目前未跑**，不要声称已验证。

## 8. 老照片（生成的）+ 文本 → 不同高清目标：自建数据集与负面结果（2026-11-13）

### 8.1 为什么必须自建

用户明确要求「老照片（生成的也可以）+ 文本 → 对应不同高清图片」，允许生成式老照片正好绕开真实历史照片无 clean GT 的死结。检索结论：**没有公开数据集同时满足三条件**。

| 公开数据 | 老照片 | 文本指令 | 一输入多 GT |
|---|---|---|---|
| Wan et al. CVPR 2020 / RealOld / Pik-Fix WACV 2023 | ✓ | ✗ | ✗（1 GT / 图） |
| GGT-100K (2026, Old Photo 6,105 对) | ✓ | ✗ | ✗ |
| CIN25 / Text2Colors（上色多解） | ✓ | ✗ | 多版本但无文本 |
| InstructPix2Pix / UltraEdit / SEED-Data-Edit | ✗ | ✓ | ✗ |
| RFIR（partial / negative prompt） | 部分 | ✓ | ✗（且全量未开放） |
| 商业修复工具的黑白 / sepia / 自然色多版本 | ✓ | ✗ | 无公开配对标注 |

### 8.2 构造

`scripts/build_old_photo_multitarget.py --groups 800`（2m30s）：

```
GT 池 = 官方 IP2P shard 0 的 edited_image (512² JPEG, SD+Prompt2Prompt 生成)
x     = make_shared_degraded(GT)   # 一张共享的合成老化老照片
        fading -> sepia -> film_grain -> scratches -> dust_spots -> vignette
y_k   = make_target(GT, target_id, strong=True),  K = 4
        natural_color / monochrome / sepia_tone / minimal_repair
text_k = 风格短语置于句首 + 官方 original_prompt 作内容 + 独立约束，3 条改写
```

产出：`data/old_photo_multitarget/` **800 组 × 4 = 3200 样本 / 4000 张 JPEG / 463.3 MB / 9600 条文本**，目标间像素 RMS **52.28**（min 37.07）。反 confound：4 个目标共享**完全相同**的 `x`，且 `x` 一律带色偏 + 颗粒 + 划痕，无法从图像反推想要哪种修复风格。

示例：`outputs/samples/old_photo_multitarget_example.png`；数据卡：`data/old_photo_multitarget/dataset_info.json`。

### 8.3 严格 A/B（唯一变量 `collapse_targets`）

配置：`configs/old_photo_multitarget.yaml` / `old_photo_multitarget_control.yaml`；
CUDA toy 主干，各 **1200 步**，`t ~ U(0.9, 1.0)`，`lr=5e-4`，`num_pairs=300`。
诊断统一用**非 collapse** 的数据集算 gap 与构造探针（否则分母为 0），只替换 checkpoint。

| 指标 | 单目标对照 | A 类（4 GT） |
|---|---|---|
| `Var_k(y_k)`（32 组） | — | **0.005665** |
| `penalty_to_gap_ratio`（8 组） | 0.80% | **9.30%** |
| `penalty_to_gap_ratio`（32 组） | **0.03%** | **7.28%** |
| `style_selectivity`（32 组） | 3.33% | **4.42%** |
| `text_needed_by_loss`（阈值 10%） | false | **false** |
| verdict | `NOT-YET-SUPPORTED`（两组 checkpoint 共用） | `NOT-YET-SUPPORTED` |

**这是一个诚实的负面结果，不要包装成验证成功。** 相比 §7.5 的 IP2P A 类 36.73%，方向一致（有 4 个 GT 时换错文本确实更疼），但量级差一个档。

### 8.4 为什么没复现（待验证的推断 `[INFERENCE]`）

1. **文本稀释**：300 组 × 4 目标 × 3 改写 = **3600 条 distinct prompt**，而 1200 步 batch=1 只覆盖 1200 个样本 —— 每个 `(group, target)` 平均只见约 1 次，且诊断探针用的是 `prompts[0]`，训练中它只以约 1/3 概率出现。哈希编码器没有泛化能力，等价于「每条文本都是新类别」。
2. **目标差异被下采样压缩**：4 个目标主要是**全局色调**变换，64×64 + patch 8 后，`image_to_tokens` 空间里 `Var_k` 只有 0.0057；IP2P A 类 0.0054 相近，但那组只有 200 组 / 800 样本，每个样本被见到 1.5 次。
3. **训练量不足**：`t_min=0.90` 而非 0.95/0.99，`x_t` 仍泄漏约 10% 的 `x0`。

### 8.5 建议的下一轮（同一套 A/B，不换指标）

- 训练时固定 `prompts[0]`（或把改写数降到 1），消除稀释；
- `t_min` 提到 **0.95**，`num_pairs` 降到 **200**，步数加到 **3000**；
- 只有 `penalty_to_gap_ratio ≥ 10%` 且严格对照仍接近 0 时，才能把 verdict 改成 `TEXT-NECESSITY-SUPPORTED`。
