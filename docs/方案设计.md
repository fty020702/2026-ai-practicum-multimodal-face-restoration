## 2. 对原方案的核对与修正

### 2.1 基座版本与 repo id 都写错过 `[FACT]`（2026-11-07 二次修正）

`FLUX.2-klein-4B` 是 **4 步蒸馏版**，只用于推理；训练必须用 **Base（50 步 flow matching）**。蒸馏版上训 LoRA/projector，loss 定义与采样轨迹都不匹配。

更重要的是**准确的 HuggingFace repo id**（BFL 模型卡 + ComfyUI 发布说明核实）：

| 用途 | repo id |
|---|---|
| 4 步蒸馏（**不要训**） | `black-forest-labs/FLUX.2-klein-4B` |
| Base BF16（50 步，训练，**唯一可加载 pipeline**） | `black-forest-labs/FLUX.2-klein-base-4B` |
| Base **FP8** 单文件（**不可直接加载**） | `black-forest-labs/FLUX.2-klein-base-4b-fp8` |
| Base NVFP4 | `black-forest-labs/FLUX.2-klein-base-4b-nvfp4` |

本项目早期写的 `black-forest-labs/FLUX.2-klein-4B-Base` **并不存在**，已在 `configs/default.yaml` / `scripts/download_models.py` 修正。

**二次修正 `[FACT]`（2026-11-07：HF API 文件清单 + 两份模型卡 + safetensors header + diffusers 0.37.1 源码）**：FP8 仓库**不是可加载的 diffusers pipeline**。它只有 7 个文件，主体是 `flux-2-klein-base-4b-fp8.safetensors`（4.09 GB），外加 3 张示例图和 README/LICENSE；**没有** `model_index.json` / `scheduler/` / `transformer/config.json` / `text_encoder/` / `vae/` / `tokenizer/`。HF 标签是 `Diffusion Single File`，模型卡明写 `No code snippets available yet for this library`。

用 HTTP Range 只读前 512 KB 解析其 safetensors header：305 个 tensor，键是 `double_blocks.0.img_attn.qkv.weight_scale` / `input_scale`、`single_blocks.0.linear1`，`_quantization_metadata` 声明 `float8_e4m3fn` + 逐层 scale —— 这是 **BFL/ComfyUI 原生格式**，不是 diffusers 的 `transformer_blocks.*`。而 `Flux2KleinPipeline` 继承 `DiffusionPipeline`，**既无 `from_single_file` 也无 FP8 量化支持**。所以 `from_pretrained(<FP8 repo>)` 必然失败；早期 `load()` 把 FP8 repo 传给 `from_pretrained`、以及把 `fp8` 映射成 `torch.float8_e4m3fn`，都是错的。

**结论**：唯一可加载的是 BF16 完整 pipeline `black-forest-labs/FLUX.2-klein-base-4B`（23.74 GB，含一份**重复的** ComfyUI 单文件 7.75 GB）。`scripts/download_models.py` 用 `allow_patterns` 排除重复单文件与示例图，实际下载 **21 个文件 / 15.98 GB**，按官方 `torch_dtype=torch.bfloat16` 加载。FP8 单文件降级为 `[UNVERIFIED]` 研究素材（`--fp8-singlefile`）；要用它必须自写反量化 + BFL→diffusers key 重映射 + FP8 linear，本项目不提供。

### 2.2 文本编码器规模被低估 `[FACT]`

原方案说"4B 模型 FP16 约 8 GB，12 GB 可以容纳，余量不大"。实际：

- Klein 4B 的 **DiT ≈ 7.75 GB BF16**（`transformer/diffusion_pytorch_model.safetensors` 实测 7.751 GB）
- 它的文本编码器是 **Qwen3-4B ≈ 8.05 GB BF16**（不是 Mistral 24B；Mistral 24B 是 FLUX.2 **dev** 的编码器）
- VAE 0.17 GB，合计 ≈ 16 GB > 12 GB，官方给的 ~13 GB 已含 offload

所以 **编码器 offload / 离线预计算是硬约束，不是可选项**；FP8 单文件不是现成解法（见 §2.1）。显存不足时训练侧默认把整个 pipeline 留在 CPU，用 `--device cpu` 先做契约验证。见 §6。

### 2.3 "离线缓存省显存" 与 "用户自由输入文本" 有矛盾 `[INFERENCE]`

训练时可以把所有 prompt 用 Qwen3-4B 在 CPU 上编码一次、缓存到 `data/text_cache`，编码器永不进显存（`src/data/text_features.py:50` `OfflineTextCache`）——这正是"只训 projector"方案最舒服的地方。

但**推理时用户会输入训练时没见过的新文本**，必须在线编码，8 GB 的编码器又回来了。解法只有三条：编码器 CPU/4-bit offload、编码完 `empty_cache()` 再加载 DiT（ComfyUI 对 FLUX.2 就是这么做的）、或牺牲自由输入改用模板。`src/backends/flux2_klein.py:144` `encode_free_text()` 实现了 offload 思路，`[UNVERIFIED]`。

### 2.4 "只训一个 projector" 的证据被过度延伸 `[INFERENCE]`

原方案用 IP-Adapter / ControlNet 证明"冻结主干只训投影层"可行。但：

- **IP-Adapter 训的不只是 projector**，还有每层新增的**解耦交叉注意力 K/V 通路**；正是这些逐层通路提供了控制力
- **ControlNet 训的是整个可训练副本**（UNet encoder 拷贝），不是投影层
- 纯 MLP projector 只有一个注入点，容量极小

所以本项目给两种模式，并明确分工（`src/condition/module.py:12`）：
- `projector_only` —— 字面意义的"只训一个 projector"，单个零初始化偏置注入
- `projector_plus_bypass` —— 推荐，每个 block 一条零初始化解耦交叉注意力（`src/condition/bypass.py:9`）

**设计上还踩到一个原方案完全没提的坑，见 §4。**

### 2.5 原方案缺可证伪实验 `[FACT]`

整份对话没有回答："怎么证明用户文本真的进去了，而不是 projector 学了个与文本无关的常数偏置？" 本项目补了 A/B/C/D 消融 + 文本扰动测试 + 同噪声控制，见 §5。

### 2.6 顺带的环境事实 `[FACT]`

2026-11-07 15:20 复测：4070 Ti 12282 MiB，其他进程常驻 **5.1 GB**，空闲 **6.9 GB**；系统内存 34.2 GB（当时可用 ~7.8 GB）；下载 15.98 GB 权重后 G 盘约 **39 GB 空闲**。这比"12 GB 卡"更紧，也意味着官方 ~13 GB VRAM 需求在本机**不满足**。权重磁盘放得下，缺的是**验证过的真实训练显存**：`preflight_flux2()` 对 CUDA 目标要求 ≥ 9 GB 空闲，否则建议先关占显存程序或走 `--device cpu` 契约验证。显存不足现在在静态 preflight 里记为 warning，不阻断 CPU 验证链。

### 2.7 **中心假设本身在 FLUX.2 上不成立** `[FACT]`（2026-11-07 新增）

这是本轮从 `diffusers 0.37.1` 源码核实出的最重要修正，见 `scripts/check_flux2_train_contract.py`（18/18 PASS）与本文 §11。

原对话的前提是「已有模型的**文本输入分支被参考图特征占据**，所以要在该分支上叠加用户文本」。但在 **FLUX.2 [klein]** 里：

- `image=[ref]` 参考图走 VAE 编码 → patchify → BN 归一化 → **拼接到 `hidden_states`（图像流）**，并用独立的 `t` 坐标 `img_ids` 区分；它**不在文本流**。
- `encoder_hidden_states = prompt_embeds`，是 **Qwen3 文本流**，原本就是空闲的、专门接收用户 prompt 的。

也就是说，"参考图占着文本分支"这个设定**不能字面套到 FLUX.2 Klein 上**。若直接把用户文本塞进 `prompt_embeds`，文本生效是模型原生能力，根本不需要我们训练 projector，消融里的 `d_text` 也无法归因到「新增文本分支」。

**本项目采取的诚实映射**（`src/system.py`）：
1. `prompt_embeds` 冻结为**全局固定的中性前导**（`NEUTRAL_PROMPT = "restore this image"`），对所有样本、所有 prompt 完全相同；
2. 参考图 token 冻结在图像流；
3. 用户文本**只**走我们新增的可训练分支（`projector_only` 的加性偏置 / `projector_plus_bypass` 的逐层旁路）。

这样 `d_text > 0` 才**只能**来自新分支，可证伪实验仍然成立。代价是：我们**主动放弃**了 FLUX.2 原生的文本接口——这是为了忠实验证原方案假设，而不是因为做不到。若以后只想做产品、不验证假设，直接用 `prompt_embeds` 更简单。

`[INFERENCE]` 这条修正也说明：原对话推荐的"成熟开源基础模型"与它描述的"参考图占文本分支"设定并非同一个模型族（后者更像 FDI / Qwen2VL-Flux）。选 FLUX.2 Klein 时，方案的目标应从"在占满的分支上挤进文本"改成"在冻结模型上用新分支注入可控文本条件"。

### 2.8 真实权重实测：dims、block 数与 dtype 修正 `[FACT]`（2026-11-07）

BF16 完整 pipeline 于 14:54 落盘（21 文件 / 15.98 GB，`verify.ok=true`）。`scripts/inspect_backbone.py` 在 CPU 上**真实加载**权重后测得，已回写 `configs/flux2_klein.yaml`：

| 项 | 早期占位 | 实测 `[FACT]` | 影响 |
|---|---|---|---|
| `in_channels` | 128 | **128** | `ref_bias_out_dim`，packed VAE latent token 宽度 |
| `inner_dim`（`hidden_dim`/`cond_dim`） | **6144（错）** | **3072**（24 heads × 128） | 旁路 q/k/v/o 投影宽度；写错直接 shape mismatch |
| `joint_attention_dim`（`text_in_dim`） | 7680 | **7680**（3 × Qwen3 hidden 2560） | 冻结 Qwen3 `prompt_embeds` |
| `transformer_blocks` | 文档写 8（错） | **5** | 只挂 5 个旁路 |
| `single_transformer_blocks` | 20 | **20** | 拼接流，不挂旁路 |
| double block 返回顺序 | `(txt, img)` | **`(txt, img)`** | `IMG_INDEX=1` 正确 |

`inspect_backbone.py` 现在额外做 `config_reconciliation`：把静态配置的四个 dim 与实测值逐项比对，不一致直接返回 `CONFIG_MISMATCH`，避免以后以晦涩的 `mat1 and mat2 shapes` 形式失败。

另一个真实权重路径上必然踩到的坑是 **dtype**：冻结主干按官方 `torch_dtype=torch.bfloat16` 加载，hook 收到的 hidden states 是 bf16，而 `TextConditionModule` 默认 float32，`img + bypass(img, text_cond)` 会直接混合 dtype 报错。修法（`src/backends/flux2_klein.py::build_flux2_system`）：文本分支显式 `.to(dtype=torch.bfloat16)`；`TextConditionModule.set_text()` 把 float32 的离线缓存转成模块自身参数 dtype。toy 路径全程 float32，该转换是 no-op，回归 `smoke_test.py` 数值逐位不变（`0.003216` / `0.000563`）。

**仍属 `[UNVERIFIED]`**：真实 GPU 端到端训练与真实消融（需 ≥ 9 GB 空闲显存）。`scripts/verify_real_forward.py` 在 CPU 上用真实权重跑一步 flow matching，验证 latent 往返、恒等性、梯度隔离与文本响应；它的结论只能证明**信号通路与梯度图正确**，不能外推成恢复质量或 GPU 训练结果。

零初始化的意义：训练第 0 步，文本分支输出**逐位为 0**，系统行为与冻结基线完全相同。这让 A/B 对照有明确含义，也避免一上来就把预训练模型带偏。`src/condition/module.py:103` 特别选择 **加偏置而不是拼 soft tokens**——拼接会改变交叉注意力 softmax 的归一化分母，即使新增向量全零也会动到输出，恒等性会悄悄失效。

## 4. 关键机制：一个真实的梯度死锁 `[RESULT]`

第一次跑 smoke test，`projector_only` 训练 40 步后 **文本响应 `d_text = 0.0`**，即不同文本输出完全相同。用 `scripts/diagnose_text_path.py` 逐层打印差异，定位到 `projector output diff = 0.0`，全链路都是 0。

手推一下（设 `W_p` = projector 末层权重，`W_b` = `ref_bias_proj` 权重）：

```
pooled = W_p @ h + b_p        初始 W_p=0, b_p=0  ->  pooled = 0
bias   = W_b @ pooled + b_b   初始 W_b=0, b_b=0  ->  bias   = 0

dL/dW_b    = grad_output @ pooled^T = 0      (因为 pooled = 0)
d(bias)/d(pooled) = W_b^T = 0                (因为 W_b  = 0)
=> 两层互相锁死，只有 b_b 能学成一个与文本无关的常数
```

**双重零初始化把梯度通路一起关掉了。** 旁路模式不受影响：它的零初始化层 `o_proj` 输入是 attention 输出（非零），`W_o` 的梯度 `grad @ attn ≠ 0`，第一步就能打开，随后梯度回流到 projector（诊断里 bypass 的 `projector output diff = 0.216`）。

修法（`src/condition/module.py:60`）：零初始化只由 projector 末层承担，`ref_bias_proj` 用 **Xavier 随机权重 + 零偏置**。初始输出仍是 `W_b @ 0 + 0 = 0`（恒等成立），但 `∂bias/∂pooled = W_bᵀ ≠ 0`，通路打开。

修完 `projector_only` 的 `d_text` 从 `0.0` → `0.003216`。**这不是调参调出来的，是改了梯度图。** 这条经验对任何"串联两个零初始化层"的设计都适用。

## 5. 可证伪实验 + 实测数值

### 设计

| 组 | 含义 | 用来判什么 |
|---|---|---|
| A `no_text` | 冻结主干，仅参考图条件 | 基线 |
| B `text_zero_init` | 未训练（零初始化）文本分支 | A 与 B 必须**逐位相同**，否则零初始化实现有 bug |
| C `projector_only` | 训练后，单注入点 | 最小方案能带来多少 |
| D `bypass` | 训练后，逐层旁路 | 推荐方案能带来多少 |

**文本扰动测试**（`src/evaluate.py:80`）：同一张退化图、同一初始噪声，配两个不同 prompt，测 `d_text = ||out_a − out_b||`。若 `d_text ≈ 0`，说明文本只是装饰，方案在该配置下**不成立**——不管 PSNR 多好看。三次采样共用同一个 `torch.Generator` 噪声，否则差异会来自噪声而非文本。

### `[RESULT]` 本地实测（2026-11-07，ChatAI env / CUDA / torch 2.5.1+cu121）

**架构验证** `src/smoke_test.py`，两种模式 T1–T6 全 PASS：

| 检查 | projector_only | projector_plus_bypass |
|---|---|---|
| 初始恒等 max diff | `0.0` | `0.0` |
| 梯度泄漏到主干的参数 | `0` | `0` |

**当前数据有一个 confound 必须记住** `[FACT]`：`RestorationDataset` 里退化类型与 prompt 严格一一对应（`src/data/dataset.py:70`），文本与图像信息冗余。在真实基座上做"文本是否有用"的结论前，应随机化内容级提示，或构造同一图像配不同任务提示的对照。否则无法排除"模型只看了参考图、完全忽略文本"这一替代解释。

### 8.1 文本在训练中究竟怎么被利用（2026-11-12）

**两条文本，别混淆 `[FACT]`**
- **FLUX.2 原生 `prompt_embeds`**：被冻结成固定常量 `NEUTRAL_PROMPT = "restore this image"` 的 Qwen3 embedding `[1,512,7680]`，所有样本逐位相同，**不携带任何用户信息**。这是刻意设计：否则 `d_text` 无法区分差异来自原生文本流还是新增分支。
- **用户文本**：数据集 `prompt` → 离线 Qwen3 缓存 `[1,512,7680]`（float32，`set_text()` 转 bf16）→ `TextProjector` → `_cond [1,512,3072]`。这是系统里唯一承载用户指令的通路。

**注入点与梯度路径 `[FACT]`**
- `projector_plus_bypass` 模式下 `fuse_condition()` 返回 `cond_ref` **原样**；文本不加在输入 latent 上，只在 5 个 double block 的 forward hook 注入 `img + bypass(img, _cond)`。bypass 是解耦交叉注意力：Q 来自 img hidden states，K/V 来自 `_cond`，`o_proj` 零初始化。
- `train.py::compute_loss` 的训练目标是 **纯 flow-matching velocity 回归**：`loss = MSE(pred, x1 - x0)`。**没有任何文本对比 / 对齐 / 一致性 / 指令跟随损失**。
- `loss.backward()` 的梯度只沿 hook 回落到 cond 的 **222,240,896** 个参数；冻结主干 **3,959,590,691** 个参数 `requires_grad=False` 且无梯度。AdamW 只更新 cond。

**所以「文本有没有用」由优化器说了算 `[INFERENCE]`**
没有任何监督项强迫模型读文本。若退化图本身已包含「该修什么」的全部信息，文本分支就是冗余的，最优解可以完全忽略它。当前 synthetic 数据 6 种退化 ↔ 6 条 prompt 一一对应，正是这种冗余。因此 `d_text > 0` 只证明「换文本能改变输出」，**不等于**「模型按指令做条件控制」，更不等于语言理解。`scripts/diagnose_text_usage.py` 用两个量化指标区分这两件事：`d_content`（同 task、不同内容约束的输出差异）与 `d_loss_wrong`（固定图像/噪声、只置换文本时的 loss 变化）。

**要让文本真正被用上，需要**
1. **去 confound**：同一张退化图配多条不同指令 —— `old_photo_dataset.py` 已实现 `prompts_per_image=3`、随机缺陷组合、instruction 噪声子集与干扰指令、真实 caption 池解耦。
2. **让文本提供图像里没有的信息**：指令描述「保留什么」（sepia 色调 / 人脸身份 / 织物纹理）而不是「修什么」（denoise / derain）。
3. **训练目标显式奖励文本响应**：文本条件 dropout（CFG 式）、同图不同文的一致性/对比正则、指令跟随辅助损失。  
   → **[RESULT 2026-11-12 修正，见 §8.2]**：这条**不是必需的**。后来的一图多目标 A/B 证明，只要让同一个 `x` 对应多个不同 `y`，并把 `t` 采样压到高噪声端，纯 velocity MSE 自己就会惩罚忽略文本的模型；无需任何对比 / 对齐损失。原先的 confound 是**数据设计问题**，不是损失函数问题。
4. **评测改为指令跟随准确率 + user study**，而不是只看 `d_text`；真实无 GT 老照片配 NIQE / CLIP-IQA。
5. **工程阻塞**：`train.py` 只接受一个 `--override`，而 `configs/old_photo.yaml` 的 `backend.name=toy`，两者不能直接叠加；且现有 10 条 Qwen3 缓存只覆盖 synthetic + eval pairs，老照片的 ~72 条 prompt 需先离线编码。

**实测证据 `[RESULT]`（2026-11-12，`scripts/diagnose_text_usage.py`）**：在真实 4B 权重 + **100 步 GPU 训练出来的 cond 权重**上，固定同一张退化图与同一噪声，只置换文本：

| 量 | 20 步 | 100 步 | 含义 |
|---|---|---|---|
| `d_text`（不同 prompt 的输出差异） | 0.019874 | **0.046817** | 文本确实能改变输出，且随训练增强 |
| `d_task`（任务词不同） | 0.020564 | 0.048883 | 任务级差异被编码 |
| `d_content`（同任务、内容约束不同） | 0.020099 | 0.046935 | 与 `d_task` 几乎相等 → **任何**不同文本都能改变输出，但不证明内容被理解 |
| `d_onoff`（文本开 / 关） | 0.138346 | 0.199567 | 文本分支整体影响最大 |
| `d_loss_wrong`（换错误文本的 loss 变化） | 0.001465 | **0.003906** | 相对 loss 仅 **1.08%**，且正好 = **1 个 bf16 ULP**（loss≈0.36） |
| `loss_off − loss_own` | 0.016602 | 0.019531 | 有文本比无文本降 loss **5.39%** |

**结论 `[INFERENCE]`**：文本分支学到的是一个**通用有益偏置**，而不是指令特定的条件控制 —— 「有没有文本」有用，「文本对不对」几乎无所谓。这正是 §8 预测的 confound 与「纯 velocity loss 无文本对比项」的联合后果。因此 `d_text > 0` **不能**作为「文本被有效利用」的证据；必须做去 confound 数据与文本响应损失，再测指令跟随准确率。详见 `outputs/logs/text_usage.json`、`text_usage_20.json`。

### 8.2 一图多目标：数据设计本身就够（2026-11-12，`[RESULT]`）

§8.1 的第 1 点（同图多条不同指令）**方向对但不充分**：`OldPhotoDataset` 的
`prompts_per_image=3` 让同一 `(x, y)` 配 3 条文本，目标图不变，MSE 最优解仍然
可以忽略文本。用户随后提出的修正是：**同一个退化图配多个不同的高清目标，
每个目标由自己的文本唯一指定**。

**数学条件**：设一组 `x` 对应 `y_0 ... y_{K-1}`。当 `t→1` 时 `x_t≈x1` 为纯噪声，
模型只能输出 `v ≈ x1 − E[x0 | ref, text]`，于是

```
无文本 MSE 下界 = Var_k(image_to_tokens(y_k)) > 0
有文本 MSE 下界 = 0
```

`Var_k(y_k)` 不需要训练即可测量。若 `t~U(0,1)`，小 t 下 `x_t≈x0` 会泄漏目标身份，
文本仍可被绕过 —— 因此 `train.py::compute_loss` 新增可选 `t_range`
（默认 `(0,1)` 是严格 no-op，`smoke_test.py` 回归 PASS、toy 数值逐位不变）。

**工程落地**：`src/data/multi_target_old_photo.py` + `multi_target_dataset.py` +
`scripts/build_multi_target_data.py`，24 张真实 DIV2K 照片 → 1 张共享老化退化图 +
K=4 个不同高清目标（natural_color / monochrome / sepia_tone / minimal_repair），
96 训练样本 / 288 条 prompt。`make_dataset()` 新增 `source=multi_target` 分发。
严格对照 `data.collapse_targets=true`：同样 4 条文本，但全部指向同一个 GT。

**A/B 结果**（`outputs/logs/ambiguity_summary.json`、图 `outputs/samples/ambiguity_ab.png`）：

| | 单目标对照 | 多目标 | 倍数 |
|---|---|---|---|
| wrong-text penalty / 理论 gap（第 1 轮，`U(0,1)`） | 0.15% | **0.56%** | 3.8× |
| wrong-text penalty / 理论 gap（第 1 轮，`U(.8,1)`） | 0.53% | **0.93%** | 1.8× |
| **wrong-text penalty / 理论 gap（第 2 轮，强差异 + `U(.9,1)`）** | **8.95%** | **60.61%** | **6.78×** |
| **样式选择性 `d_text_wrong / d_text_onoff`（第 2 轮）** | **5.36%** | **11.08%** | **2.07×** |

第 2 轮 `gap = 0.00547`（目标间像素 RMS 48.61/255），verdict
`TEXT-NECESSITY-SUPPORTED`。**结论：不用加任何文本响应损失，纯 velocity MSE
在高噪声 t 下就能迫使模型使用具体指令。** 完整对标与限制见
`docs/一图多目标数据集调研.md`。

**边界 `[FACT]`**：这是 toy 主干（随机冻结）+ 哈希文本编码器的结果，证明的是
数据设计与优化目标机制；**不是**语言理解、恢复质量或真实 FLUX.2 的结论。
真实基座多目标训练需先用 `scripts/precompute_prompts.py --override
configs/multi_target_flux2.yaml` 重跑 288 条 Qwen3 离线缓存（CPU 约 3 h / 10 条）。

## 11. FLUX.2 [klein] 结构契约（不加载权重即可核实）`[FACT]`

两份脚本都只做源码检查 + 模拟 block，秒级、不需要 GPU、不需要权重，报告写在 `outputs/logs/`。`README.md` 中提到的"会静默出错的那类"事实都在这里。

| 事实 | 证据 | 为什么危险 |
|---|---|---|
| 训练必须用 `FLUX.2-klein-4B-Base`（50 步），不是 4 步蒸馏版 | `Flux2KleinPipeline.__init__(is_distilled=False)`；`num_inference_steps=50` | 蒸馏版上训 projector，loss 定义与采样轨迹都不匹配 |
| 文本编码器是 `Qwen3ForCausalLM` + `Qwen2TokenizerFast`，不是 Mistral 24B | `pipeline.__init__` 源码 | 显存预算差一倍（§2.2） |
| `prompt_embeds` 可直接传入 `__call__` | `inspect.signature(__call__)` | 离线文本缓存可行 |
| Qwen3 hidden states 取 `(9, 18, 27)` 层堆叠并 reshape 成 `[B,S,3*H]` | `_get_qwen3_prompt_embeds` 源码 | `text_in_dim` 必须是 `3*hidden`，不是 `hidden` |
| `transformer_blocks`（double）与 `single_transformer_blocks` 同时存在 | `Flux2Transformer2DModel.__init__` | single block 吃拼接流，**不挂旁路** |
| `inner_dim = num_attention_heads * attention_head_dim` | 同上 | 旁路 q/o 投影的输出宽度 |
| **double block 返回 `(encoder_hidden_states, hidden_states)` = `(txt, img)`** | `Flux2TransformerBlock.forward` 源码 | 旁路 hook 必须用 `img_index=1`；用 0 会把文本注入文本流、对生成图毫无作用 |
| 参考图拼进 `latents`（图像流），`encoder_hidden_states=prompt_embeds` | `__call__` 源码 `torch.cat([latents, image_latents], dim=1)` | §2.7 中心假设修正 |
| `noise_pred = output[:, :N_generated]`，参考图 token 被丢弃 | `__call__` 源码 | 旁路 delta 只影响前 N 个 token 的速度 |
| `timestep` 在 transformer 内部 `*1000` | `Flux2Transformer2DModel.forward` | 我们的 flow-matching `t∈[0,1]` 直接传入即可 |
| single block 前 `cat([txt, img])`，之后 `[:, num_txt_tokens:]` 去掉文本 | 同上 | 印证只在 **5 个** double block 挂旁路是对的（实测值，§2.8） |
| VAE latent 用 `vae.bn` 的 running mean/var 归一化/反归一化 | `_encode_vae_image` / `__call__` 尾部 | 少这一步 latent 分布错，恢复结果全废 |

`scripts/check_flux2_contract.py` 还做了一个模拟 `(txt, img)` block 的 hook 测试：`img_index=1` 时**只有 img 流变化**，`img_index=0`（toy 默认）时相反。这是把"会静默出错"变成"可证伪"的关键一条。

## 12. 三个维度不兼容与分发设计 `[FACT]` + `[RESULT]`

toy 主干把一切都折叠成一个 `dim`（512/128）。FLUX.2 有**三个互不相同的宽度**：

| 宽度 | 来源 | 用在哪 |
|---|---|---|
| `in_channels`（默认 128） | `transformer.config.in_channels`；`x_embedder = Linear(in_channels, inner_dim)`；`_pack_latents` 输出 token 宽度 | **packed VAE latent token**。`projector_only` 的加性偏置 `fuse_condition(ref)` 必须加在这个空间 |
| `inner_dim`（= heads × head_dim） | `transformer.inner_dim`；double/single block 的 hidden stream | **逐层旁路** hook 的 q/o 投影宽度；`block_dims = [inner_dim] * n` |
| `joint_attention_dim`（实测 7680） | `transformer.config.joint_attention_dim` = `3 × Qwen3 hidden_size` | 冻结 Qwen3 `prompt_embeds`，即 `text_in_dim` |

**踩过的坑**：`TextConditionModule.fuse_condition()` 把 `ref_bias_proj` 的输出加到 `ref` 上。早期 `ref_bias_proj = Linear(cond_dim, hidden_dim)`，在 FLUX.2 上会得到 `[B,1,inner_dim]`，而 `ref` 是 `[B,M,in_channels]` → 直接形状不匹配。修法是给 `TextConditionModule` 加**可选** `ref_bias_out_dim`（默认 `hidden_dim`，toy 逐位不变），由 `apply_runtime_config()` 设为 `in_channels`。这就是 `src/system.py` 适配器能复用 `compute_loss()` / `sample()` / `evaluate_checkpoint()` 而不用改任何调用方的原因。

**分发契约**（`src/system.py`）：`train.py::build_system` 与 `inference.py::load_checkpoint` 只在 `backend.name == "flux2_klein"` 时转到 `build_flux2_system()`，返回与 toy 完全相同的 `(backbone, cond, cache)` 三元组：

```
Flux2BackboneAdapter.image_to_tokens / tokens_to_image / ref_tokens_from_image / forward(x_t,t,ref)
    ≡ ToyMMDiT 的同名方法（接口层），因此 compute_loss / sample / 消融脚本零改动
```

`projector_plus_bypass` 挂在 `transformer_blocks`（`img_index=1`）；`projector_only` 走 `fuse_condition(ref)` 把 pooled 文本偏置加到参考图 latent token 上，经 `x_embedder` 自然传播进主干。`NEUTRAL_PROMPT` 固定不变，保证 `d_text` 可归因（§2.7）。

**回归证据 `[RESULT]`**：接入分发后重跑 `smoke_test.py`（两种模式 T1–T6 全 PASS，`d_text` 仍为 `0.003216` / `0.000563`，可训练参数仍为 `41,600` / `239,744`）、`run_ablation.py`（A/B 仍逐项相等 `6.986 / 0.0152 / 0.000000`，C/D `d_text` 仍为 `0.000834` / `0.000479`）、`check_flux2_contract.py`（全 PASS）、默认 toy 训练（2 步成功）。**toy 的 `[RESULT]` 没有被这次改动污染。**

`[RESULT]` / `[UNVERIFIED]` `Flux2BackboneAdapter` 本身：CPU 侧真实权重验证由 `scripts/verify_real_forward.py` 给出（§9）；GPU 端到端训练、offload 与梯度检查点交互仍待 ≥ 9 GB 空闲显存后核对。
